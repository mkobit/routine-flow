# Docs site guidelines

These instructions apply when working in `docs/`, the Docusaurus 3 + React site.
`docs/README.md` has the bare commands for a general audience; this file covers the conventions and carve-outs behind them.

`docs/` is a standalone bun project, not part of a bun workspace with the plugin root.
It has its own `package.json`, `bun.lock`, and `bunfig.toml`, and there is no `workspaces` field anywhere.
Run `bun install` inside `docs/` once before the first local dev or build.

## Local development and build

From the repo root, `bun run docs:dev` runs `cd docs && bun run start` (dev server at localhost:3000) and `bun run docs:build` runs `cd docs && bun run build` (static output to `docs/build/`).

## Adding a page

The sidebar is autogenerated from `docs/docs/*.md` by `docs/sidebars.ts` (`{type: 'autogenerated', dirName: '.'}`), ordered by each file's `sidebar_position` frontmatter number.
Current order: intro.md=1 (also `slug: /`, the site root), getting-started.md=2, design-notes.md=3, usage-notes.md=4, screenshots.md=5, demo.md=6.
A new page needs a `sidebar_position`; the next free integer is 7, or use a decimal / renumber to insert it earlier.

The top navbar is a separate, hand-maintained list: `themeConfig.navbar.items` in `docs/docusaurus.config.ts` (currently just the GitHub link).
A regular docs page never touches the navbar — only add an entry there for a genuine top-level link.

## Lint carve-out

`docs/` has no eslint config of its own; the repo-root `eslint.config.mts` lints it, and root `bun run lint` covers it.
Two blocks in that config carve `docs/` out, because it follows Docusaurus ecosystem conventions (no semicolons) rather than plugin domain rules:

- `functional.configs.strict`, `functional.configs.stylistic`, and `stylistic.configs.recommended` all carry `ignores: ['docs/**']`, so the FP-purity and repo-stylistic presets do not apply.
- A dedicated `files: ['docs/**/*.ts', 'docs/**/*.tsx', 'docs/**/*.mts', 'docs/**/*.cts']` block turns off `obsidianmd/prefer-file-manager-trash-file`, the whole `functional/*` family, and the `@typescript-eslint/no-unsafe-*` family — mirroring the carve-out already given to tests and e2e code.

General hygiene rules still apply to `docs/`: `no-console`, `eqeqeq`, `curly`, `no-restricted-imports` (bans barrel `**/index` imports), `@typescript-eslint/consistent-type-assertions` (no `as` casts), `@typescript-eslint/consistent-type-imports`, and `no-restricted-globals` banning `Date`.
Use native `Temporal` instead of `Date` (see the footer copyright year in `docusaurus.config.ts`, `Temporal.Now.plainDateISO().year`).

## CI

`.github/workflows/docs.yml` runs on changes under `docs/**` with `docs/` as the working directory for every step.
A push to `main` builds and deploys to GitHub Pages via `actions/deploy-pages`; any PR runs the build job only, as a check, with no deploy.

## Known gotchas

- **`docs/bunfig.toml` forces the Bun runtime**: it contains only `[run]` / `bun = true`, which makes node-shebang binaries (docusaurus, etc.) run under Bun instead of a system node. There is no root-level `bunfig.toml`; this setting is docs-specific because `docs/` is a standalone bun project.
